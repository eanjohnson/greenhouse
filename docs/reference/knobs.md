# Knobs and title configs

What this covers: every runtime switch the loader reads, how the reader functions behave, the per-title
config format, and the non-numeric control files.
Where the code is: `src/loader/guest_loader.cpp` (`GhCfgNum`, `GhCfgNumZ`, `GhCfgTrace`, `GhTitleFromJson`,
`GhTitlesLoadDir`, `GhTitleMatch`, `GhTitleKnobDefault`), title configs in `corpus/titles/*.ghtitle.json`.

The knob tables below were generated by scanning the source for `GhCfgNum(` / `GhCfgNumZ(` calls, so names
and defaults are the ones the code uses. Descriptions were written by hand from the code and comments at each call site; where one is terse,
the call site is the authority.

## 1. What a knob is

A knob is a file named `gh_<name>.txt` in the app's `LocalState` folder that holds one unsigned number.
There is no central registry: a knob exists because some function calls

```cpp
GhCfgNum (L"gh_<name>.txt", "GH_<NAME>", default);   // zero cannot be expressed
GhCfgNumZ(L"gh_<name>.txt", "GH_<NAME>", default);   // zero is a real value
```

Both are defined next to the title-config code in `src/loader/guest_loader.cpp`. To add a knob, add a call.
To find what a knob does, grep for its file name.

### Precedence

For `GhCfgNum`, highest first:

1. Environment variable `GH_<NAME>`, if set and nonzero. Only useful on a desktop test host; a packaged
   app on the console has no way to set it.
2. The file `LocalState\gh_<name>.txt`, if present and nonzero.
3. The matched title config's value for that knob (`early` or `knobs`), if nonzero.
4. The default in the call.

`GhCfgNumZ` uses the same order, except that a file or environment value of `0` is accepted and returned,
and a title value of `0` is honoured too.

The title config is consulted only when the LocalState file does **not exist**. A file that exists but
holds `0` (for `GhCfgNum`) or no digits falls straight through to the call's default, skipping the title value.

### Rules that bite

| Rule | Consequence |
|---|---|
| `GhCfgNum` returns the default when the value is 0. | You cannot switch off a default-on `GhCfgNum` knob by writing `0`. The log shows `file/ZERO->default`. Knobs that need an "off" use `GhCfgNumZ` or start their values at 1. |
| The reader keeps digits only. | Values are **decimal**. `0x10` is read as `010` = 10. Addresses and masks must be converted (for example 0x1000 is written `4096`). |
| The file may be ASCII or UTF-16LE. | Either works; anything that is not a digit is ignored. |
| A LocalState file beats the title config. | A stale knob file left on the console silently overrides the shipped per-title default, and a file holding `0` replaces the title value with the built-in default. Delete knob files after an experiment; do not zero them. |
| Most call sites cache the result in a function-local `static`. | A knob is read once per process. Changing the file needs a relaunch. |
| Some knobs are read before a game is chosen. | Those must be in the title config's `early` block; see section 3. |

### Checking that a knob was read

`GhCfgTrace` logs one line per knob file the first time it is read:

```
CFG gh_scache.txt = 3 (default/NOFILE)
CFG gh_lazy_mb.txt = 1 (title)
CFG gh_pso_guard.txt = 2 (file)
```

The source tag is one of `env`, `file`, `title`, `title/installed`, `title/next`, `default/NOFILE`,
`default/NODIGITS`, `file/ZERO->default`. A run that was meant to test a knob and has no `CFG` line for it
tested nothing. `GhCfgNumZ` reads are only traced when the value came from a title config; a few call
sites print their own `CFG ... (Z)` line.

## 2. Setting a knob

Write the file into the app's LocalState folder (Device Portal file explorer, or the helper scripts in
`toolchain/`), then relaunch:

```
LocalState\gh_veh_max.txt      contents: 12
```

Delete the file to return to the default.

## 3. Title configs

A title config supplies knob defaults, launch arguments and install metadata for one game, so that a user
never has to write knob files. Schema id `greenhouse.title/1`.

| Where | Role |
|---|---|
| `corpus/titles/<id>.ghtitle.json` | Source of truth in the repository. |
| `<install>\guest\titles\` | Packaged copy, read at startup by `GhTitlesLoadDir`. |
| `LocalState\titles\` | Per-console override. A file here replaces the packaged config with the same `id`. Max 1 MiB. |

### Fields

| Field | Type | Meaning |
|---|---|---|
| `schema` | string | Must be `greenhouse.title/1`. |
| `id` | string | `[a-z0-9._-]{1,64}`. Identity for overrides. |
| `name` | string | Display name. |
| `match.exe` | string | Bare file name of the game executable. This is what a launch is matched on. |
| `match.installProbe` | string | Relative path under the games folder whose existence means "installed". |
| `match.launch` | string | Relative path of the executable to start, when it is not at the install root. |
| `match.steamAppId` | number | Steam app id. A config that names one applies to that app only, which separates two games that share an executable name. |
| `match.steamBranch` | string | Branch to install (for example a 64-bit beta branch). |
| `match.steamSkipDepots` | number[] | Depots not to download. |
| `match.workshop` | bool | Title uses Workshop content. |
| `requires.loader` | string | Minimum loader version `a.b.c.d`. |
| `requires.services` | string[] | Runtime services the title needs, for example `steam-runtime`. |
| `early` | object | `gh_<name>: number` knob defaults that are read **before** a game is picked (device creation patches, shader-cache shim, guest stack size, pager, keep-alive, raw input, pipeline-cache hiding). |
| `knobs` | object | `gh_<name>: number` knob defaults read after the title is known. |
| `psoDeny` | string[] | 32-hex-digit pipeline digests to refuse; stand-in for a `gh_pso_deny.txt` file. |
| `args` | string | Command-line arguments appended to the executable path. |
| `input` | string | Name of an overlay input profile, for example `builtin-wasd`. |
| `seed` | string | Folder under `guest\seed\<seed>\localstate\` copied into LocalState on first launch, never overwriting (`GhSeedCopyTree`, `SEED` log lines). Used for config files a game needs to start in a sane state. |

Unknown top-level keys are reported in the log and ignored.

Minimal example:

```json
{
  "schema": "greenhouse.title/1",
  "id": "example",
  "name": "Example Game",
  "match": { "exe": "example.exe", "steamAppId": 123456 },
  "args": " -novid",
  "knobs": { "gh_dsound": 1 }
}
```

### Matching and the built-in default

- `GhTitleMatch(exe, app)` picks the config. Matching is by executable name, narrowed by Steam app id when
  the config names one.
- A game with no config whose executable is named `*-Win64-Shipping.exe` gets the built-in Unreal default
  (`GhUnrealDefault`): arguments ` -dx11`, `gh_gpu_vendor` = AMD, `gh_rawinput` = 2.
- A user-uploaded custom game gets no title match at all.
- `GhTitleBegin` logs a `TITLE` line naming the config in effect.

### Early knobs and the relaunch

Some knobs are consumed while the host starts, before the launcher has let the user pick a game. A title
default for such a knob cannot apply to the process that is already running. When a picked title has
`early` values that differ from what the process read (`GhEarlyNeedsRelaunch`), the host writes a marker
and restarts itself so that the early reads come from the picked title (`STAGE=title_relaunch`).
If a knob listed under `knobs` turns out to have been read before the title was chosen, the log says
`TITLE late <knob>`; move it to `early`.

| Config | Notable settings |
|---|---|
| `hl2`, `portal` | 32-bit Source: `gh_x86_native=1`, `gh_dsound=1`, `-condebug -novid`. Portal also seeds a config folder. |
| `hl` | GoldSrc: `gh_x86_native=1`, `gh_x86_steam=1`, `gh_dsound=1`, software renderer (`-soft`). |
| `garrysmod` | 64-bit branch, Workshop, `gh_dsound=1`, single-process Chromium arguments. |

## 7. Control files that are not numbers

These live in LocalState too, but carry text. "Consumed" means the loader deletes the file after acting.

| File | Consumed | Contents and effect |
|---|---|---|
| `ghguest.txt` | no | File name of the guest executable to run when no launcher selection is made. |
| `ghcmd.txt` | no | Replaces the guest's whole command line. |
| `ghdenydll.txt` | no | DLL names the loader refuses to load for the guest, one per line. |
| `ghreg_*.txt` | no | Persisted virtual registry hive (see `docs/architecture/filesystem-registry.md`). |
| `ghpad.txt` | yes | One synthetic gamepad pulse. Tokens: `A B X Y LB RB START BACK LS RS LT RT`, d-pad `DUP DDOWN DLEFT DRIGHT`, left stick `UP DOWN LEFT RIGHT`, analog `LX= LY= RX= RY=`, hold time `T=<ms>` (default 400, clamped 50..5000). Note `DOWN` is the stick; the d-pad is `DDOWN`. |
| `gh_remap.txt` | no | Input remapping table (`src/loader/gh_input.h`). |
| `ghtrace.txt` | no | Tracepoints. See `docs/reference/diagnostics.md`. |
| `gh_peek.txt` | no | Addresses to print next to each memory sample. |
| `gh_poke.txt` | yes | `<hexaddr> <hexdword>`: write one dword into the guest. |
| `gh_watchw.txt` | yes | Hardware write watchpoints (8-byte aligned addresses). |
| `gh_dumpthreads.txt` | yes | One upload = one all-thread stack dump. |
| `gh_handles.txt` | no | Handles whose state is logged every 3 s. |
| `gh_snap.txt` | yes | Writes `LocalState\gh_snap.bmp`, a 480x270 copy of the back buffer. |
| `gh_activate.txt` | yes | Releases the activation message burst held by `gh_rawinput` bit 16. |
| `gh_pso_deny.txt` | no | Pipeline digests to refuse, one 32-hex-digit digest per line. |
| `gh_rt_keep.txt`, `gh_vs_skip_list.txt`, `gh_xfw_keys.txt`, `gh_var_sel.txt` | no | Lists of resource or shader keys for the investigation knobs of the same family. |
| `gh_diag_local.txt` | no | Presence forces the diagnostic log into LocalState. |
| `gh_diag_cap_mb.txt` | no | Diagnostic log size cap in MB (1..512). |
